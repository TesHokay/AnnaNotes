## P0. Приложение не открывается без интернета

Проверка опубликованной версии (`curl -I`):

| Запрос | Ответ |
|---|---|
| `/` | 200 |
| `/index.html` | **307 → `/`** |
| `/sw.js` | 200, `no-cache` |
| `/registerSW.js` | 404 (не используется — регистрация из бандла, это нормально) |

### Причины

1. **Резервный документ для навигации кэшировался по адресу, который Cloudflare отдаёт редиректом.** Workbox кэшировал `index.html` и отдавал его на все навигационные запросы без сети (`navigateFallback: '/index.html'`). Cloudflare Workers и Pages отвечают на `/index.html` редиректом 307 на `/` (так работает обработка HTML по умолчанию). Ответ, полученный через редирект, ненадёжен как ответ Service Worker на навигацию: Safari отклоняет навигационные ответы с редиректом и показывает «нет подключения к сети».
2. **Установленное на экран «Домой» приложение на iPadOS хранит Service Worker, кэш и IndexedDB отдельно от Safari.** Если сайт открыли в Safari и сразу добавили на экран «Домой», у установленного приложения своего кэша ещё нет. Его нужно хотя бы раз запустить с интернетом и дождаться окончания кэширования. Обойти это технически нельзя; можно только явно показывать готовность.
3. **Слишком большой precache: 205 файлов, 4,6 МБ.** Установка Service Worker выполняется по принципу «всё или ничего»: если загрузка любого файла прервётся (переход в фон, нестабильная сеть), SW не установится. 2,3 МБ из этого объёма — CMap-файлы и шрифты pdf.js, нужные только части PDF.
4. **Обновления проверялись раз в час**, хотя iPadOS не закрывает PWA, а приостанавливает их. Новая версия могла не обнаруживаться сутками.
5. **Настройки записывались с задержкой 250 мс.** При быстром закрытии последний выбор (например, «онбординг пройден») терялся. Найдено E2E-тестом.

### Исправления

- `vite.config.ts`: запись precache для `index.html` переименовывается в `/` (`manifestTransforms`), `navigateFallback: '/'`. Теперь в кэше лежит ответ 200 на тот же URL, который отдаёт Cloudflare. Из `navigateFallbackDenylist` убраны `.html`-адреса, чтобы открытие `/index.html` без сети тоже работало.
- CMap-файлы и шрифты pdf.js исключены из precache и кэшируются при первом использовании (`runtimeCaching`, CacheFirst). Precache: 23 файла, 2,7 МБ.
- `src/pwa/register.ts`: проверка обновлений при возвращении приложения на передний план, при восстановлении сети и раз в час. Ошибки регистрации и состояние SW собираются для диагностики. Флаг `offlineReady` выставляется и при повторном запуске, если SW уже активен.
- Новая страница `#/diagnostics` (Настройки → «Диагностика PWA и хранилища»). Работает без сети и показывает: управляет ли SW страницей, scope, наличие оболочки `/` в precache, версию и commit сборки, опубликованную версию (`/version.json`), состояние и версию схемы IndexedDB, объём хранилища, режим запуска (вкладка или установленное приложение). Если приложение установлено, но не готово к офлайну, страница подсказывает открыть его один раз с интернетом.
- `wrangler.jsonc`: конфигурация Workers static assets с `not_found_handling: single-page-application`.
- `scripts/serve-like-cloudflare.mjs`: локальный сервер, повторяющий поведение Cloudflare (307 для `.html`, SPA-fallback). На нём теперь работают E2E-тесты.
- Настройки записываются сразу; с задержкой — только ползунки, и их запись принудительно завершается на `visibilitychange`/`pagehide`.

### Проверка

- E2E `offline.spec.ts`: (1) после первого визита и перезагрузки без сети создание и редактирование тетради работают; (2) **холодный старт**: новая вкладка без сети открывает `/`, `/index.html` и диагностику («Офлайн-запуск готов»). Оба сценария проходят в Chromium на сервере с поведением Cloudflare.
- На физическом iPad не проверено. Сценарий описан в `IPAD_TEST_CHECKLIST.md`.

## Обнаружено, исправляется на следующих этапах

| Область | Проблема | Причина в коде |
|---|---|---|
| Ластик | Задержки, курсор движется рывками | Каждое событие `pointermove` вызывает `model.apply` → копирование и сортировку массива страницы, перерисовку растра (dirty rect со слоем маркера на всю страницу), колбэки в React. Каждый проход перебирает все штрихи страницы (только отсечение по bbox, без пространственного индекса) |
| Перелистывание | Рывки | В кадре синхронно рендерится до 2 растров страниц; соседние страницы не готовятся заранее (растр и элементы появляются, только когда страница уже на экране); миниатюры перерисовываются в основном потоке одновременно с прокруткой |
| Почерк | Дрожание, угловатость | Фильтр сглаживает вход, но центральная линия рисуется по исходным редким точкам без сплайна и передискретизации: на быстрых участках остаются углы. В конце штриха добавляется «сырая» последняя точка — возможен крючок. Сглаживание настраивается одно на все перья, без пресетов |
| Ручки | Нет каллиграфии; стили отличаются только `minRatio` | Ширина зависит только от давления, а не от направления |
| Фигуры | Нельзя менять размер по осям, заливку, скругление | Фигуры сохраняются как обычные штрихи |
| Темы | Только розовая светлая и тёмная, при запуске возможно мерцание | Тема применяется после загрузки настроек из IndexedDB |
| Импорт | Нет ZIP и массовой очереди | — |
